# ua-cryptography-ffi

The algorithms and signature formats of this workspace as one native library, `ua_cryptography`: a C ABI for
Windows, macOS, Linux, Android and iOS, and JavaScript bindings for the browser (WebAssembly).

## API

Every operation exists in both bindings under the same name: `ua_dstu7564_calculate_hash` in C is
`dstu7564CalculateHash` in JavaScript.

| Area | Operations |
|---|---|
| GOST 28147-89 | `gost28147_encrypt`, `gost28147_decrypt` (simple substitution, whole 64-bit blocks, any DKE) |
| GOST 34.311-95 | `gost34311_calculate_hash`, `gost34311_begin_hash` (any DKE and initial value) |
| DSTU 7564 | `dstu7564_calculate_hash`, `dstu7564_begin_hash` (256, 384, 512 bits) |
| hashes fed in parts | `update_hash`, `end_hash`, `free_hash_state` (C); `HashState.update`, `HashState.end` (JavaScript) |
| DSTU 7624 | `dstu7624_encrypt_block` / `decrypt_block`; ECB, CBC, CFB, XTS `…_encrypt` / `…_decrypt`; `ofb_apply_gamma`, `ctr_apply_gamma`; CCM, GCM `…_encrypt` / `…_decrypt`; `cmac_calculate_mac`, `gmac_calculate_mac`; `wrap_key`, `unwrap_key` |
| DSTU 4145 | `dstu4145_generate_key_pair`, `calculate_public_key`, `validate_public_key`, `sign_hash`, `sign_hash_with_presignature`, `verify_hash`, `sign_message`, `verify_message` (GOST 34.311), `encode_signature`, `decode_signature`, `generate_random_bytes` (Appendix А) on the curves of tables Г.1 and Г.2 |
| key stores | `create_key_store` (JKS, a key on a curve of table Г.1, a self-signed certificate), `get_certificate`, `get_key_store_entries` |
| certificates | `get_certificate_details` |
| signatures | `sign` (CAdES, XAdES, ASiC-S, ASiC-E at levels B, T, LT), `verify` (any of them, a JSON report) |

DSTU 4145 takes integers big-endian (d, e, r, s and D = S‖R of 5.10), Q compressed (6.9) and a hash code most
significant byte first (5.9). The national PKI reverses its digests before signing and stores D reversed:
see docs/signature-formats.md.

### C

```c
#include "ua_cryptography.h"

UaBuffer hash = {NULL, 0};
UaBuffer error_message = {NULL, 0};
UaBytes data = {(const uint8_t *)"message", 7};
if (ua_dstu7564_calculate_hash(data, 256, &hash, &error_message) != UA_STATUS_OK) {
    fprintf(stderr, "%.*s\n", (int)error_message.len, (const char *)error_message.data);
    ua_free_buffer(error_message);
    return 1;
}
/* use hash.data, hash.len */
ua_free_buffer(hash);
```

- Every function returns a `UaStatus`; the kind of a refusal is the status, its text goes to `error_message`
  (pass NULL to skip it).
- Inputs are lent for the call: `UaBytes` (an optional input is absent when its `data` is NULL), NUL-terminated
  UTF-8 strings, arrays of `UaBytes` / `UaNamedBytes` with their counts.
- Outputs are `UaBuffer` values the caller owns, written only on `UA_STATUS_OK`, each released once with
  `ua_free_buffer`.
- A panic never crosses the ABI: it is `UA_STATUS_INTERNAL`.
- Reports (`get_key_store_entries`, `get_certificate_details`, `verify`) are UTF-8 JSON; an invalid signature is
  `UA_STATUS_OK` with `"is_valid": false`.
- The functions are thread-safe; a `UaHashState` is used by one thread at a time.

`include/ua_cryptography.h` is generated by `build_scripts/ffi-header.sh` (cbindgen) and checked by CI;
`include/module.modulemap` imports it into Swift as `UaCryptography`. `tests/c/smoke_test.c` is a complete example.

### JavaScript

```js
import init, { dstu7564CalculateHash, sign, verify, SignatureFormat, SignatureLevel, SignatureHash } from './ua_cryptography.js';

await init();
const hash = dstu7564CalculateHash(new TextEncoder().encode('message'), 256);
const signature = sign(keyStore, password, undefined, [{ name: 'a.txt', content }], SignatureFormat.AsicE,
  SignatureLevel.B, SignatureHash.Dstu7564, false, []);
const report = verify(signature, [], [rootCertificate], []);   // report.is_valid
```

A refusal is thrown as an `Error` whose `name` is the kind: `InvalidArgument`, `UnreadableInput`, `WrongPassword`,
`AuthenticationFailed`, `ServiceFailure`. `tests/js/smoke_test.mjs` is a complete example.

## Packages

Built by `.github/workflows/release.yml` on a version tag and attached to the GitHub release:

| Archive | Contents |
|---|---|
| `windows-x64`, `windows-arm64` | `ua_cryptography.dll`, its import library `ua_cryptography.dll.lib`, the static `ua_cryptography.lib`, `.pdb` |
| `macos-universal` | `libua_cryptography.dylib` (install name `@rpath/…`) and `libua_cryptography.a`, arm64 + x86_64; macOS 11+ |
| `linux-x64`, `linux-arm64` | `libua_cryptography.so`, `libua_cryptography.a`; glibc 2.35+ |
| `android` | `jniLibs/{arm64-v8a,armeabi-v7a,x86,x86_64}/libua_cryptography.so`, API 21+, 16 KB pages |
| `ios` | `UaCryptography.xcframework`: static libraries for devices (arm64) and simulators (arm64, x86_64); iOS 13+ |
| `wasm` | the npm package unpacked: the ES module, its Node.js entry, `ua_cryptography_bg.wasm`, TypeScript declarations |

The native packages carry the header in `include/` (the XCFramework in each slice's `Headers/`). A program linking
a static library also links the system libraries listed in `native-static-libs.txt` beside it, as rustc reports
them for the platform (`build_scripts/ffi-static-libs.sh`).

The WebAssembly build is also the npm package [`ua-cryptography`](https://www.npmjs.com/package/ua-cryptography)
(`npm/`: its `package.json`, Node.js entry and README), published by the release workflow once the author approves.

Locally: `cargo build --release -p ua-cryptography-ffi` (this machine), `cargo ndk … build -p ua-cryptography-ffi`
(Android), `build_scripts/npm-package.sh` and `build_scripts/npm-smoke-test.sh` (the npm package).

## Boundaries

- The curves are the recommended ones of Appendix Г; DSTU 4145 over other domain parameters is not exposed.
- The browser build reaches no network: it signs at level B, verifies offline and refuses `T`, `LT` and online
  verification with `InvalidArgument`.
- No JNI and no Swift or Kotlin wrappers: they belong to the projects that use the library.
- The C ABI and its JSON are this crate's own: a change of either is a change of the library's version.

## Dependencies

The workspace crates `ua-cryptography-gost`, `ua-cryptography-dstu7564`, `ua-cryptography-dstu7624`,
`ua-cryptography-dstu4145`, `ua-cryptography-gf2m`, `ua-cryptography-pki` (with feature `http` on native platforms);
`num-bigint`, `rand_core`, `serde`, `serde_json`, `time`. On `wasm32-unknown-unknown`: `wasm-bindgen`, `js-sys`, and
`getrandom` / `time` with their browser features. Tools: `cbindgen` for the header, `cargo-ndk` and `wasm-pack` for the
packages.

`unsafe` code lives in `src/c_abi` only, where the pointers of the C ABI are read and written.

## Visibility

Private to this workspace (`publish = false`); the packages are attached to GitHub releases, and publishing to a
registry (npm, Maven, CocoaPods) is the author's decision.

## Why not a ready crate

`uniffi` and `diplomat` generate bindings for several languages from one description, but each imposes its own
object model and runtime on the consumers; the brief here is a plain C ABI, with the Kotlin and Swift wrappers kept
in their own repositories.
